# ForestGuard AI 演示与算法说明

> 本系统是交互式仿真原型，不是实战系统。图像、火情识别、火势、环境、地形、装备及传感器均为模拟或示意；未经实测验证，不得用于真实飞行、灭火或安全决策。界面上的部分链路、AI 模型、遥测和统计项也只是演示。

## 1. 启动与演练

1. 按 README 安装 PySide6 并运行 `python main.py`，使用演示账号登录。登录前仿真暂停。
2. 登录后装备从四个所属基地开始，两架无人机开始巡逻；经过 10 秒真实时间后启用随机起火，后续由仿真步推进火情。随机自动起火最多保留三个活跃火点。
3. 系统为火点自动调度；可疑火点先分配无人机侦察，确认后进入扑救调度。无需人工确认调度。
4. 设备按照各自配置的路径到达作业点，满足喷水条件时消耗水量、压制火势。火点强度降为零后相关设备返回所属基地。
5. 退出登录停止计时；重新登录会重置火点、设备、轮岗及本次演练日志。可使用界面倍速；设置中的刷新间隔影响仿真推进频率，数值不表示经过校准的物理时间。

随机起火位置避开地面障碍栅格；手动指定到不可达区域的火点可能无法扑灭。即使火点可达，装备不足、急停、返航或其他状态也可能延迟或阻止扑救。

## 2. 巡逻与基地轮岗

- 第一轮由北山和东坡基地各派一架无人机，下一轮由西林和南谷基地各派一架，然后循环。两架都完成本轮后才切换；下一组基地缺少可用无人机时等待，不从其他基地冒充该组。
- 每架无人机沿多条往返航带扫描，空中路径由设备自己的导航算法计算；两架从相反方向开始。演示传感器视幅为地图归一化半径 `0.11`，沿实际飞行路径记录已覆盖栅格；航带扫描结束后对遗漏栅格补扫。达到模拟的整图栅格覆盖后才算完成一轮。
- 未完成巡逻的无人机不参与火情调度。低电量或过温仍会中断巡逻并安全返航，休整后继续原进度；设备离线时，同基地有可用无人机可接替并继承进度。完成巡逻后返回所属基地。
- 视幅、速度及覆盖模型仅为演示，不考虑真实相机遮挡、地形、通信或飞行安全，不能作为实际巡检覆盖证明。

## 3. 多火点调度与接替

系统按每个火点独立分配装备，已分配给其他火点的设备不会被抢占。对已确认火点，编组目标为两架无人机和三台地面机器人；可疑火点先派无人机核查。装备不足时系统持续重试，不保证一定能补足或扑灭。

扑救推荐对可用设备按下列演示公式评分：

```text
综合得分 = 0.40 × 能力匹配 + 0.25 × 距离得分
         + 0.20 × 剩余电量 + 0.15 × 载荷百分比
```

候选设备须空闲、未分配火点、未处于未完成的巡逻任务，且满足电量、温度和水量条件。此评分是简单启发式，不能证明任务最优，也不保证实际往返续航。协作页派遣日志展示对应评分依据。

过温、低电量或水耗尽后，设备停止作业并返回所属基地。系统优先让同类型可用设备接替原任务及目标点；没有可用设备时保留缺口并在后续仿真步重试。可疑火点的侦察机退出后也会重新尝试派出侦察机。

## 4. 喷水、休整与装备状态

- 设备必须关联对应活跃且已确认的火点，处于执行喷水任务状态、距该火点不超过 `0.06` 地图归一化距离、有水且系统未急停，才能产生压制及喷水线。喷水线指向设备所属火点，不指向其他火点。
- 温度 **超过 60℃** 或电量 **低于 30%** 自动返所属基地；温度超过 60℃的装备卡片显示红色。低电量与温度的颜色分级见 README。
- 过温 / 低电 / 水耗尽设备返回基地后休整、充电并补水，温度降至 35℃及以下、电量至少 40%、水箱补满才退出休整状态。这些数值只是仿真阈值。
- 总览的“林区实时态势”隐藏行驶路线、保留有效喷水线；导航页展示所选设备的剩余路线与终点旗帜。地图上的喷水和第一人称喷水特效均取自仿真状态。

## 5. 单设备路径规划

在“自主导航与路径规划”页选择装备，并单独设置算法、风向、风速和坡度。设置改变后，从该设备当前位置重新计算路线；巡逻、侦察、赶赴火点和返航使用同一设备的设置，地图读取相同的剩余路径点。设备实际沿折线移动，而非另走直线。

- **A***：静态栅格上的启发式路径搜索。
- **Dijkstra**：不使用目标启发式的栅格搜索。
- **风险加权 A***：在搜索代价中加入演示性风向、坡度、热源和障碍邻近代价，内部名称为 `RL-A*`，但不是训练过的强化学习模型。不同算法可能因地形或起终点相同而生成相同路线。
- 地面机器人遵守静态障碍栅格，路径不可达时停止并提示，不以直线替代；无人机演示中可飞越地面障碍，未建模真实空域、禁飞区和机间动态避碰。
- 未实现 RRT*；原界面选项已移除。参数、轨迹、速度和代价均是示意，不可用作实际导航。

## 6. 火情分析与隔离带

- 可见光和红外模式使用静态演示图片；有活跃火情和无火情时分别选择对应素材。检测框、分类分数及状态由仿真驱动，不是模型对真实图像的识别结果。
- 多火点预测对单火点概率场逐像元取最大值并估算合并面积；此方法不是经过验证的火势预测。可选择火点查看对应策略与实际任务装备。
- 隔离带是具有宽度的弧形示意，算法尝试沿风向外移并采样避开联合预测区；找不到可行线时标记人工复核。离散栅格、有限外移和地图边界等限制可能导致方案不可行，不可用于现场作业。

## 7. 协作日志与界面

多机器人协作页实时列出活跃火点编组、设备任务、阶段、电量与温度，并记录发现、侦察、派遣、到场、退出、接替、等待补派和扑灭等仿真事件；可按火点筛选。日志倒序显示，最多保留最近 200 条，仅保存在当前演练内，重置后清空。日志不是装备间真实通信，也不表示已实现路径冲突协商。

装备管理页按电量和温度风险排序，并可打开第一人称演示视角。方向键 / 按钮改变的是演示视角；喷水特效取自仿真实际喷水状态。系统设置中的部分链路、模型、统计与操作为界面示意，不代表接入硬件或真实服务。

## 8. 运行与测试

运行方式、依赖、演示账号和测试命令见项目 [README](../README.md)。GUI 测试需要系统 Qt 图形库和可用的平台插件；`QT_QPA_PLATFORM=offscreen` 只能在具备这些依赖时使用。缺少图形库时，QtCore 仿真测试仍可单独运行，不能据此声称 GUI 测试通过。

## 9. 慢速自动演示脚本

运行 `python demo_autoplay.py`：先展示登录页约 3 秒，自动使用演示账号登录并以 1× 速度运行；随后展示巡逻、等待正常自动起火，再依次停留在自主导航、多机协作、火情分析、装备管理和总览。各主要页面停留约 15～25 秒。若等待火情超时，脚本继续展示无火情状态，不强制生成或扑灭火点。关闭窗口或退出登录停止自动切页；结束后应用与仿真继续运行。仅供演示，不适用于实战。
